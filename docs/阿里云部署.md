## 运行方式

前端使用 Next.js 静态导出，Nginx 在 80 端口提供页面。其他端口的网站保留原配置。模拟器由 `robot-motion-simulator.service` 管理，使用独立用户 `robot-motion`，开机自启，失败自动重启；仅监听服务器 `127.0.0.1:3101`，由 Nginx `/ws` 反向代理。

生产前端自动使用当前站点的 WebSocket 地址；本地开发继续使用 `ws://127.0.0.1:3101`。关键帧 ID 使用 `crypto.getRandomValues`，兼容普通 HTTP 公网地址。

## 检查

```sh
ssh aliyun 'systemctl status robot-motion-simulator.service --no-pager'
ssh aliyun 'journalctl -u robot-motion-simulator.service -n 30 --no-pager'
ssh aliyun 'nginx -t'
```

本地运行 `node scripts/check-deployment.mjs` 检查公网首页、书写动画、页面切换、模型加载、HTTP 下记录新关键帧、WebSocket 状态同步、工作台刷新以及原导航入口。报告位于 `artifacts/deployment/checks.json`。

## 构建与更新

PowerShell 构建：

```powershell
$env:STATIC_EXPORT='1'
node node_modules/next/dist/bin/next build
Remove-Item Env:STATIC_EXPORT
```

上传 `out/`、`server/simulator.mjs`、`src/lib/robot-config.json`、`deploy/` 与解引用后的 `node_modules/ws/` 到新的 `releases/<时间戳>` 目录。模拟器运行时的 `package.json` 使用 `deploy/runtime-package.json`。

运行 `python3 deploy/normalize-static.py out` 补齐当前 Next.js Windows 导出的分段预取文件路径。发布包包含本地已验证的纯 JavaScript `ws` 依赖与许可证，不依赖服务器重新下载版本。文件权限设为 644、目录权限设为 755。

后续更新应先验证新目录，再原子切换 `current` 软链接并重启模拟器。`deploy/install-aliyun.sh` 是首次部署脚本，已有本站时会拒绝执行，避免覆盖正在使用的配置。

## 恢复原导航首页

```sh
cp /opt/robot-motion-studio/backups/20261005T012710Z/frontend /etc/nginx/sites-available/frontend
nginx -t && systemctl reload nginx
systemctl disable --now robot-motion-simulator.service
```

站点发布目录仍保留，可再次切换使用。
