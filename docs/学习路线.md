# 边做边学的路线

先运行项目，完成一次“改姿态 → 记录 → 回放 → 导出”的操作，再从下面第一课开始。每课结束后，用自己的话写出解释，并提交一次有明确目的的修改。

## 1. 看懂场景和模型

操作：旋转视角，观察机械臂、地面、阴影和轨迹。关闭轨迹，再恢复。

读代码：`src/components/robot-scene.tsx` 的 Canvas、camera、light、Grid，以及 `public/models/rms-arm.urdf` 的 visual。

概念：Scene 组织对象；Camera 决定从哪里看；Geometry 描述形状；Material 描述表面；Light 影响受光材质；Renderer 将场景绘制到画布。React Three Fiber 把 React 组件映射成 Three.js 对象，仍需要理解这些对象。

练习：改变视角 FOV，比较近大远小的变化；修改一种材质的 roughness，观察高光。

验收：能指出模型、相机、灯光分别由哪里创建，能解释改 CSS 为什么不能直接改变机械臂形状。

## 2. 理解 link、joint 和坐标变换

操作：依次调整 J1、J2、J3；选中 J2 后打开坐标轴。记录哪些零件会一起运动。

读代码：URDF 的 parent / child / origin / axis / limit，以及 `robot.setJointValues()`。

概念：link 是刚性零件，joint 连接父子 link。origin 描述相对父坐标系的初始位置与方向，axis 决定在关节坐标系里绕哪个轴旋转。父节点世界变换会传递到子节点。

数学只需先理解：子节点世界矩阵 = 父节点世界矩阵 × 子节点局部矩阵。角度转弧度为 `degrees * Math.PI / 180`。本项目所有运动关节都是有限位的 revolute，不能把它们当成无限旋转的 continuous。

练习：在 URDF 中将 J2 的轴从 `0 1 0` 改成 `1 0 0`，同时更新 `robot-config.json` 的轴标签，观察变化。然后恢复；再改变 upper_arm 长度及下一级关节 origin，观察它们为什么要配套修改。

验收：能解释“改变 visual 长度，为什么下一段机械臂没自动移到新末端”。

## 3. 自己推一次关键帧插值

操作：将播放位置移到两帧中间，切换线性 / 平滑插值，再比较靠近端点的位置。

读代码：`src/lib/motion.ts` 的 `sampleMotion` 与 `advanceTime`。

设左帧角度 a、右帧角度 b，当前比例 t，则线性结果为 `a + (b - a) * t`。平滑模式先使用 `t*t*(3-2*t)` 调整比例，再插值。它在两端减速，但不等同于机器人的动力学轨迹规划。

时间使用 `delta * speed` 推进，不能每帧固定加一个角度，否则 60Hz 和 144Hz 屏幕会播放不同速度。本项目直接按有限位关节角度插值，避免最短角路径跨越限位。

练习：手算 J1 从 0 到 1 弧度、历时 2 秒，在 0.5 秒时的两种插值结果。编写一个测试验证答案，再尝试增加一种插值方式。

验收：能讲清楚暂停、seek、循环结束各自怎样确定姿态；能解释为什么一条动作可以只有一个关键帧。

## 4. 从姿态得到末端轨迹

操作：修改 J2 / J3 并记录关键帧，观察青色曲线变化。改变视角，确认曲线在三维空间中。

读代码：`robot-scene.tsx` 中 clone、`updateMatrixWorld(true)`、`tool_tip.getWorldPosition()`。

正向运动学是在关节角度已知时求末端位置。本项目用 URDF 的层级变换实现，沿动作采样 161 个姿态，取每个姿态的工具末端世界坐标并连线。逆运动学则是给目标位置反求关节角度，当前没有实现。

练习：将轨迹采样从 161 个点改为 41 / 321 个点，比较曲线和计算开销。注意端点、长动作和剧烈运动。

验收：能区分关节空间轨迹和笛卡尔空间轨迹，说明轨迹曲线为什么不能证明没有碰撞。

## 5. 实时状态经过了什么路径

操作：点击连接模拟设备，确认关节输入被锁定，模型持续变化。另开终端单独运行服务进行断线实验。

为了单独停止模拟器，可分别运行 `pnpm dev:web` 与 `pnpm simulator`，此时不要再运行合并的 `pnpm dev`。

读代码：`server/simulator.mjs` → `use-device.ts` → `telemetry.ts` → `robot-scene.tsx`。

模拟器每 50ms 发送一帧；浏览器校验模型、消息序号、角度，再写入最多 120 帧的缓冲。渲染时使用本机接收时间和 100ms 延迟，在相邻状态之间插值；不假设机器人与电脑时钟完全一致。

断线后逐步增加重试间隔，最多 5 秒。重新连接后清理旧缓冲，避免与新会话混用。连接存在但 3 秒没有有效状态时主动断开重试。消息停止时保持最后姿态，不向未知未来外推。

练习：将发送周期改为 200ms，再将显示延迟从 100ms 改为 250ms；比较延迟和流畅度。再故意发送超限角度或重复序号，观察这些消息被拒绝。

验收：能解释为什么消息频率和屏幕刷新率不同，为什么时间戳不能直接当作端到端网络延迟，为什么前端数值面板不必每帧更新。

## 6. 做一次有证据的性能检查

读代码：场景中的渲染循环、`disposeRobot`，以及 Zustand 的订阅位置。

本项目每帧直接更新 Three.js 对象；编辑面板以约 20Hz 刷新；性能数字约 2Hz 刷新。轨迹仅在动作或模型变动时重新采样。模型重载时按 Set 去重释放 geometry / material，FK 克隆共享资源，不能自行释放共享 geometry。

练习：多次点击“重新加载模型”，记录 geometry 数量是否回到稳定水平；开启 / 关闭坐标轴和轨迹，观察变化。使用浏览器性能面板录制一次播放，找到主线程长任务。

记录模板：操作系统、浏览器、显卡 / 软件渲染、分辨率、DPR、模型规模、采样时长、指标口径、改动前后值。FPS 和 draw calls 只是观察项，不能单独证明没有内存泄漏；GPU 资源数也不等于完整内存字节数。

验收：能指明哪个对象由谁创建、谁释放，能解释缓存复用与资源释放之间的关系。

## 7. 延伸方向

完成以上练习后，每次选择一项：

- 任意 URDF + 网格资源目录导入，处理相对路径、package 路径和加载失败。
- 使用 React Flow 编排姿态、动作、等待和循环节点，明确执行与取消语义。
- 末端拖动配合逆运动学，先做简单平面双关节求解。
- MQTT Broker + MQTT over WebSocket，比较发布订阅与当前单连接通信。
- 骨骼蒙皮动画：另加载一个带骨骼的 glTF，学习 Skeleton、权重与 AnimationMixer。
- 接入物理引擎或机器人仿真后端，再研究碰撞、接触和动力学。

## 怎样用 AI 配合学习

每次给 AI 一个具体任务，例如“解释 J2 为什么会改变 tool_tip 的世界坐标，指出经过的节点，再给我一道手算练习”。接着自己改代码或回答，再让 AI 校验。

一次只改一个概念。保留 `docs/我的学习记录.md`，记录现象、原因、修改、验证结果。面试时优先讲这些亲自验证过的问题。

## 可用于简历的事实边界

完成并理解现有功能后，可以描述：基于 React Three Fiber 与 URDF Loader 开发六轴机械臂动作编辑工具，实现关节控制、关键帧插值、末端轨迹及 WebSocket 模拟设备状态同步；设计消息校验、有界缓冲和自动重连。

需要更多实践才能声称：熟练机器人控制、真实设备调试、骨骼动画、MQTT、物理仿真、WebGPU 或已完成可量化性能提升。AI 生成的代码要通过自己的修改、测试和解释转化为掌握的经验。
